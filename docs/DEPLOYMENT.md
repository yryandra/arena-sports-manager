# Deploy ARENA with GitHub, Vercel and Atlas

Use a personal GitHub repository, a Vercel Hobby project and your existing Atlas free cluster. Do not enable paid add-ons. The Vue frontend and Express API share one Vercel domain; MongoDB stores records and administrator sessions.

## Configuration

Import `yryandra/arena-sports-manager` into Vercel. Keep the root directory at the repository root, not `client`. `vercel.json` defines dependency installation, the build and static output. Use Node.js 24.x. The API entry point is `api/index.js`; `/api/*` and `/about` route to that function.

Set these variables in the production environment before deploying:

| Variable | Value |
| --- | --- |
| `STORAGE_MODE` | `mongodb` |
| `MONGODB_URI` | Your Atlas connection string, stored as a Secret |
| `MONGODB_DB` | `arena` |
| `ADMIN_USERNAME` | `yryandra` |
| `ADMIN_PASSWORD_HASH` | The complete scrypt hash generated by `npm run admin:setup`, stored as a Secret |

The password setup command stores its hash in your ignored local `.env`. Never commit that file or paste credentials into issues, screenshots or documentation. The browser does not receive database credentials or the hash. Do not prefix secrets with `VITE_`.

The API checks that browser writes originate from its own host, so `CLIENT_ORIGIN` is unnecessary for this same-origin deployment. HTTPS enables the Secure session cookie. Preview deployments should use their own database and environment configuration if you enable them for development.

Atlas must permit connections from the hosting environment. Use a database user restricted to the `arena` database. Vercel's default egress addresses are dynamic; any broader Atlas network access rule should be deliberate and paired with strong database credentials. No network access settings are changed by the application.

## Seed and verify

With the local `.env` pointed at the intended database:

```bash
npm run seed
npm run test:mongodb
npm run check
```

Seeding refuses to change populated athlete, event or result collections. Database verification creates temporary records and removes them. The default test suite is isolated from Atlas.

After deployment, check the public homepage, `/api/health`, `/about` and all six views. An unauthenticated write must return 401. Sign in with the password you chose, register a fictional athlete, then remove the test record and sign out. Production must be publicly accessible; preview deployment protection can remain enabled.

## Updates and interview explanation

Push changes to `main` after `npm run check` passes. When the Vercel GitHub connection is enabled, a push triggers a new deployment. GitHub Actions independently runs tests and the frontend build; it does not automatically prevent Vercel from deploying a failing commit.

Explain the deployment in four steps:

1. **GitHub holds the source and history.** The lockfiles make installations reproducible, and CI checks changes on Linux.
2. **Vercel builds Vue into static assets.** The browser downloads these files and requests JSON from the same domain.
3. **A Vercel Function runs Express.** Warm instances reuse initialization and a small MongoDB connection pool. Local JSON storage is not used because function filesystems are ephemeral.
4. **Atlas persists data and sessions.** A login remains valid across different function instances, and the API independently enforces permissions for every write.

For password changes, regenerate the hash locally, update the production secret and redeploy. Existing sessions remain valid until logout or their eight-hour expiry; revoke documents in the `adminsessions` collection if immediate sign-out is required. The current design has one administrator, no recovery email flow and no MFA.
